# Workshop Expectation Questions

These questions help the event organizer and participants align on goals, readiness, and outcomes before the workshop begins.

---

## For the Event Organizer

### Audience & Context

1. What is the primary audience for this workshop — internal engineers, customers, partners, or a mixed group?
2. What skill levels are represented? Are participants self-sorted into beginner/intermediate/advanced, or will you assess and assign tracks?
3. How many participants are expected, and will they work individually or in pairs/teams?
4. Is this a one-time event or part of an ongoing enablement series?

### Logistics & Environment

5. Will participants use their own machines, shared cloud environments, or pre-provisioned devcontainers?
6. Are all participants guaranteed to have an active GitHub Copilot subscription before the event?
7. Has the devcontainer been tested in the target environment (local Docker, Codespaces, or corporate VPN restrictions)?
8. What is the planned duration? Which tracks and labs will fit within that time box?

### Outcomes & Success Criteria

9. What does a successful workshop look like for your organization? (e.g., adoption metric, team habit change, demo deliverable)
10. Will there be a follow-up session or a way for participants to continue practicing after the workshop?
11. Are there specific Copilot features or workflows you want participants to leave having used at least once?
12. How will you collect feedback — post-session survey, live retrospective, or GitHub issues on this repo?

### Constraints & Risks

13. Are there any corporate policies that restrict Copilot usage, network access, or data shared in prompts?
14. Is there a backup plan if Copilot is unavailable or rate-limited during the session?
15. Are there facilitators for each track, or is one person running all levels simultaneously?

---

## For Participants

### Before the Workshop

1. Have you completed all setup steps in [doc/setup.md](doc/setup.md) — VS Code Insiders installed, Agents app open, and signed in with a Copilot-enabled account?
2. Which track are you attending — Beginner, Intermediate, or Advanced?
3. How would you describe your current experience with GitHub Copilot? (Never used / Occasional tab completions / Regular chat user / Daily agentic workflows)
4. What language or tech stack will you use during hands-on exercises?

### Goals & Expectations

5. What is the one thing you most want to be able to do with Copilot by the end of this workshop?
6. Are you here primarily to learn new skills, validate existing habits, or explore agentic automation?
7. Is there a real task, codebase, or project you want to bring to the workshop to work on?
8. What does "good enough" look like for you — a working demo, a changed habit, or a shipped PR?

### Current Pain Points

9. Where do you currently feel Copilot suggestions are unreliable or unhelpful for you?
10. Have you ever had Copilot generate code you didn't fully understand before merging it? How did you handle it?
11. Do you currently write tests before or after using Copilot to generate code?
12. Have you tried using Copilot for anything beyond code completion — documentation, specs, CI workflows, or issue triage?

### Advanced Track (additional questions)

13. Are you comfortable reading and editing GitHub Actions workflow YAML?
14. Have you worked with GitHub Issues as a trigger for automated workflows before?
15. Do you have a repository where you could set up the issue-to-Copilot automation after the workshop?
16. What guardrails or review steps would you require before trusting an autonomous agent to open pull requests on your behalf?
